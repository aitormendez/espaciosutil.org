# Actualización de NGINX — 21 de noviembre de 2026

Producción de Espacio Sutil (`134.209.21.17`) se actualizó de `1.29.6-1~noble` a `1.31.9-1~noble` para corregir CVE-2026-123007 y CVE-2026-123633. La misma instancia atiende `espaciosutil.org` y `matomo.espaciosutil.org`. La operación se ejecutó mediante Ansible, con respaldo de configuración y del paquete anterior, y reinicio completo de NGINX. No se desplegó código WordPress ni se modificaron bases de datos.

## Estado verificado

Todos los procesos NGINX activos ejecutaban la versión 1.31.9, sin binarios eliminados pendientes de reinicio. El proceso maestro se inició el 21 de noviembre a las 12:05:22 UTC (13:05:22 en Madrid). La configuración se conservó íntegra según las huellas de sus archivos; `nginx -t` y `dpkg --audit` terminaron correctamente.

Las sondas HTTPS con HTTP/2 comprobaron la portada, el acceso de WordPress, su API REST, el curso, la suscripción y una lección. Matomo respondió con su formulario de acceso y `matomo.js`, y se comprobó la conexión a su base de datos y la existencia de su sitio configurado. La petición `rec=0` al receptor devolvió el rechazo esperado sin registrar una visita. Estas pruebas no incluyen pagos, envío de formularios ni recorridos autenticados completos.

## Gestión con Trellis

La gestión de NGINX permanece en [server.yml](../../trellis/server.yml) y su [rol existente](../../trellis/roles/nginx/tasks/main.yml). Los playbooks y sondas creados para esta intervención se retiraron; no forman parte de la infraestructura mantenida. Después de la retirada, la simulación de `server.yml` con la etiqueta `nginx` y `nginx_package_state=latest` terminó con `changed=0` y sin errores.

Desde `trellis/`, el flujo ordinario de actualización se prepara con:

```sh
trellis exec ansible-playbook server.yml -e env=production --tags nginx -e nginx_package_state=latest --limit 134.209.21.17 --check --diff
```

Revisar la simulación antes de aplicar el mismo comando sin `--check --diff`; comprobar después la configuración, el servicio y la versión del binario de los procesos activos. Una instalación de paquete no demuestra por sí sola que todos los procesos hayan incorporado el parche.

Durante esta intervención el refresco global de APT encontró un cambio de etiqueta del repositorio PHP de Ondřej. Se refrescó únicamente la fuente firmada de NGINX para completar la actualización; no se cambió la confianza del repositorio PHP ni se aceptó su nueva etiqueta. Este asunto de PHP sigue siendo independiente y puede bloquear futuros refrescos globales. La simulación de Ansible no acredita que ese bloqueo esté resuelto.

## Recuperación

El respaldo remoto está en `/var/backups/nginx-security-20261121/`, con permisos privados: configuración NGINX, inventario de paquetes y paquete anterior. No es una imagen completa del servidor. Una vuelta a NGINX 1.29.6 reintroduciría las vulnerabilidades, por lo que debe priorizarse corregir la configuración manteniendo el paquete parcheado.

Referencia: [avisos oficiales de seguridad de NGINX](https://nginx.org/en/security_advisories.html).
